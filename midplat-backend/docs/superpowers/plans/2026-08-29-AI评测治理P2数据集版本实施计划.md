# AI 评测治理 P2 数据集版本实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 在 AI 中台后端交付可创建、编排、冻结和派生的不可变评测数据集版本，并以案例快照保证历史运行可重复。

**实施状态：** 已完成（2026-08-30）。实际迁移链已演进为 V1–V22：V21 建立数据集版本结构，V22 补足条目编排与派生的乐观锁推进字段。

**架构：** 新增 `evaluation.dataset` 限界上下文。数据集保存稳定身份，版本保存状态与快照哈希，条目在草稿期引用案例、冻结时复制完整案例快照；冻结版本的所有写入口由领域状态机拒绝。

**技术栈：** Java 17、Spring Boot 3.2.5、Spring Data JPA、Flyway、PostgreSQL/H2、JUnit 5、MockMvc。

**规格：** `docs/superpowers/specs/2026-08-29-AI数据飞轮与评测治理模块设计及建设跟踪.md`

## 全局约束

- 数据库生产契约固定为 PostgreSQL 与 `READ_COMMITTED`，H2 PostgreSQL 模式只用于快速回归。
- 数据集创建时自动生成 V1 草稿；同一数据集同时最多存在一个草稿。
- 冻结版本必须至少包含一个案例，且所有案例均为 `ACTIVE + REVIEWED`。
- 冻结时将名称、分类、严重级别、输入、期望、评分器和内容哈希复制到条目快照；之后案例变更不影响冻结版本。
- 版本号只递增、不复用；新草稿从最新冻结版本复制案例引用并重新等待冻结。
- 所有创建、编排、冻结和派生动作追加脱敏审计记录。
- 每个生产行为先写失败测试并确认失败原因，再写最小实现。

## 实际验证结果

- 真实 PostgreSQL 16.14、Hikari 显式 `TRANSACTION_READ_COMMITTED`：`EvaluationDatasetLocalPostgresTest` 5 项通过，并在真实 Spring 连接查询 `current_setting('transaction_isolation')` 断言为 `read committed`。空随机 schema 完成 V1–V22 共 22 条 SQL 迁移；版本号、单草稿、条目案例与条目顺序唯一约束均由数据库拒绝重复写入。
- 两个并发派生请求以相同 `expectedVersion` 发起，仅 1 个成功；最终只有 1 个 V2 草稿，版本号为 `[1, 2]`，没有复用。
- 两个数据集以相反编排顺序冻结同一对案例均成功；显式 `lock_timeout` 触发 PostgreSQL `55P03` 后转换为 `PessimisticLockingFailureException`，测试遍历异常 cause 链断言该 SQLSTATE，既有全局处理器对应 HTTP 409。
- HTTP 补测验证派生和冻结的过期 `expectedVersion` 均为 409；请求 JSON 的缺失/null 均为 400，400/409 的 `detail`、`instance` 不回显外部 ID 或请求正文。
- 联合 API 回归 25 项通过；全量 `mvn test` 发现 104 项，其中 89 项执行通过、15 项条件式跳过、0 失败、0 错误；`mvn -DskipTests package` 成功。
