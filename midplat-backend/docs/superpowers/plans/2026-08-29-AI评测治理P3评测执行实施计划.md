# AI 评测治理 P3 评测执行实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 基于冻结数据集和中台平台配置创建可恢复的批量评测任务，保存不可变目标快照、逐题结果、质量、延迟、Token 与成本。

**架构：** `evaluation.run` 保存任务和结果，`evaluation.evaluator` 提供无网络确定性评分器，`evaluation.target` 通过端口调用 OpenAI 兼容模型。任务创建先持久化为 `QUEUED`，事务提交后由受限线程池执行；每题外部调用不占用数据库事务，结果以独立事务落库。

**技术栈：** Java 17、Spring Boot Async/Event、JPA、Java HttpClient、Jackson、Flyway、JUnit 5、MockMvc、JDK HttpServer。

**规格：** `docs/superpowers/specs/2026-08-29-AI数据飞轮与评测治理模块设计及建设跟踪.md`

## 全局约束

- 只允许冻结数据集版本创建运行。
- 运行快照保存模型端点、模型名、Prompt 名称/版本/正文、参数和价格，不保存 API Key。
- 运行时从当前模型配置读取凭据，实际端点、模型、Prompt 和参数使用已保存快照。
- 单任务内案例串行；网络和 5xx 最多重试 2 次，4xx、配置错误和评分错误不重试。
- 单案例失败不能丢失其他结果；部分执行错误产生 `PARTIAL`。
- 历史结果不可覆盖；人工评分只更新待人工复核结果并追加审计。
- 日志、异常和轨迹不得包含 API Key、案例输入、期望或完整输出。
