# AI 评测治理 P5 实验门禁实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 对基线与候选运行给出逐案例改进/退化结论，并依据可审计策略生成不可变发布门禁决策。

**架构：** `evaluation.experiment` 只读聚合两个终态运行和结果，不新增可变实验表；`evaluation.gate` 保存策略与追加式决策。比较与门禁算法均为纯领域计算，控制器只负责编排和契约转换。

**技术栈：** Java 17、Spring Data JPA、Flyway、Jackson、JUnit 5、MockMvc、PostgreSQL/H2。

**规格：** `docs/superpowers/specs/2026-08-29-AI数据飞轮与评测治理模块设计及建设跟踪.md`

## 全局约束

- 只有终态运行可比较或生成门禁决策。
- 比较要求数据集快照哈希一致；不同快照返回 HTTP 409。
- 逐案例分类固定为 `IMPROVED/UNCHANGED/REGRESSED/ERROR/REVIEW_REQUIRED`。
- 门禁结论固定为 `PASS/FAIL/REVIEW_REQUIRED`。
- `CRITICAL` 案例失败必定 `FAIL`；MANUAL 未评分必定 `REVIEW_REQUIRED`。
- 门禁决策只追加不覆盖，保存策略快照、证据 JSON 和时间。
- 质量、成本、平均延迟与 P95 延迟均使用运行落库统计，不从前端重算。
