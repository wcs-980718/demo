## 六字段统计口径

| 字段 | 确定口径 |
| --- | --- |
| `totalCases` | 当前评测案例总数 |
| `reviewedCases` | `review_status = REVIEWED` 的案例总数 |
| `frozenVersions` | 当前状态为 `FROZEN` 的数据集版本总数 |
| `runningRuns` | 状态为 `QUEUED` 或 `RUNNING` 的运行总数 |
| `latestTerminalPassRate` | 最近终态运行中，`PASSED / (PASSED + FAILED) × 100`；ERROR、CANCELLED、当前待审不进入分母，无已确定结果时为 0 |
| `regressionCount` | 最近终态候选相对最近一个完整可比终态基线的 Task 1 `REGRESSED` 案例数；历史中不存在完整可比基线时为 0 |

“最近终态”只包含 `COMPLETED`、`PARTIAL`、`FAILED`、`CANCELLED`，按 `completed_at desc, id desc` 稳定选择。基线候选先限定同一 `platform_id`、同一冻结 `dataset_version_id`，再在选择阶段用双向 `NOT EXISTS` 要求其结果集合与最新候选按 `case_id + snapshot_content_hash` 完全一致，最后按相同稳定顺序选择最近一个真正可比的终态。紧邻但只含部分案例的 retry 会被跳过，不会遮住更早的完整可比基线。这比只比较相同版本哈希更保守，明确要求同一冻结快照身份。

回归必须先满足候选与基线的案例数量相等，并能按 `case_id + snapshot_content_hash` 一一完整对齐。分类与 Task 1 保持一致：ERROR、CANCELLED、`PENDING + reviewRequired=true` 不判回归；基线 PASSED 而候选非 PASSED 为回归；同属通过或非通过且两边都有分数时，候选分数下降为回归。普通 FAILED 不会天然计为回归：测试夹具中最近候选有 3 个 FAILED，但只有 2 个满足上述回归条件，能阻止用“失败数”冒充“回归数”的实现。

## 读取一致性与边界

- `EvaluationOverviewService` 使用 `@Transactional(readOnly = true, isolation = REPEATABLE_READ)`。
- 所有候选/基线选择、完整对齐、通过率与回归聚合在同一条 SQL 语句中执行，因此同一次响应不混合多个语句时点；在 PostgreSQL MVCC 下各 CTE 共享同一语句快照。
- 总览不会调用 `EvaluationExperimentService.compare`，没有给 Task 1 的比较流程增加外层事务，也没有改变其只读 `REPEATABLE_READ` 约束。
- 查询没有用户可控 SQL 片段或参数，不读取高敏正文列，只返回六个聚合数字。跨域能力仅是读端口，未暴露或注入其他域仓储。

## 已知边界与后续风险

- `latestTerminalPassRate` 与 `regressionCount` 是请求时点的当前快照，不是历史时序指标；如果需要趋势图，应新增持久化指标或按时间窗口查询契约，不能改变现有六字段含义。
- 可比基线要求相同 `dataset_version_id`，即使两个版本内容哈希偶然一致也不比较；这是为可解释性选择的保守边界。
- 历史中完全不存在结果集合完整对齐的基线时返回 0，表示“没有可辩护的回归数”，不能解释为质量无退化；前端如需区分“零回归”和“不可比较”，需另行扩展显式可比性字段并协调契约。
- Flyway 9.22.3 会对 PostgreSQL 16.14 给出未完全声明支持的版本警告；V1–V25 已在该真实方言通过，但仍应由基础设施任务升级 Flyway 后重跑迁移回归。
- 首期复用中台统一身份与权限，不在评测治理模块内部重建企业 RBAC。
- 前端总览页面、菜单点击主流程、伪 OpenAI 链路与浏览器最终端到端仍待后续任务完成。
