# 智能体使用与接入

入口：智能体平台左侧“API 接入”。也可以从智能体详情、编排页面或版本页面进入。`/agent-hub/use` 路由保持兼容，打开后直接显示接入说明与调用示例，不再提供“直接使用”。

调试、上线版本和运行记录请到“运行记录”。

## 创建后怎样接入

保存草稿 → 发布版本 → 上线版本 → API 接入。生成编排只会保存经过检查的草稿，不会直接上线。每个新会话使用当前已上线版本；修改草稿或仅发布版本不会改变当前调用行为。

页面按已上线版本列出可调用任务。未上线、执行服务不可用或服务配置不明时，不生成可执行示例。只读身份不能获取项目凭证。管理员且可写时，需要明确打开“查看项目凭证”才会读取，关闭弹窗后清除展示值。

## 统一接口怎样选择智能体

所有项目共用 `/api/runtime/agent` 接口前缀，实际完整地址随前端使用的后端网关展示，支持独立入口、内嵌入口和显式 API 前缀。

- `Authorization: Bearer <本项目凭证>`：决定访问哪个项目的智能体。
- `taskKey`：选择该智能体已上线版本中的任务。
- `input`：需要处理的文本，最长 20,000 字符。
- `idempotencyKey`：本次提交的唯一标识，最长 64 字符。同一次网络重试保持请求内容和键完全一致；不同任务提交使用新键。
- `sessionId`：可选，继续上次会话时传入返回的 `session_id`。会话固定任务、发布版本与调用身份，有效期 12 小时；不能同时提交多个运行。

调用方无需为每个节点调用不同接口，也不能通过请求覆盖角色、模型、编排、项目或运行环境。含条件、并行和汇合的流程使用 `POST /runs` 完整执行。

页面不再提供开发 / 预发布 / 生产切换。业务数据仍按服务端运行配置读取；界面不展示、也不切换环境。历史链接中的 `environment` 参数不会改变实际数据源。

## 完整调用流程

| 步骤 | 方法与相对路径 | 返回或用途 |
| --- | --- | --- |
| 提交任务 | `POST /runs` | HTTP 202，保存返回的 `id` 和 `session_id` |
| 查询结果 | `GET /runs/{id}` | 终态为 `succeeded`、`failed`、`cancelled`；成功读取 `output`，失败读取 `error` |
| 查询过程 | `GET /runs/{id}/events?after=0` | 每页最多 200 条，将最后一条 `sequence` 用作下一页 `after` |
| 取消运行 | `POST /runs/{id}/cancel` | 继续查询最终状态，取消不是同步完成保证 |
| 关闭会话 | `POST /sessions/{id}/close` | 单次调用完成后关闭；会取消该会话中仍在执行的任务 |

以上请求使用同一项目凭证。页面默认展示 Java 提交示例，并可切换 React；不提供 Python 或 cURL 选项。

- **Java（默认）**：Java 17 + Jackson + JDK HttpClient，从服务端环境变量 `MIDPLAT_TOKEN` 读取凭证，POST 到当前平台 `/runs`，判断 HTTP 202 已受理后输出返回 JSON。
- **React（可选）**：React 18 TypeScript 组件，请求体使用当前页面的 taskKey / input / idempotencyKey，调用同源占位路径 `/api/ai-agent/runs`。该路径只是调用你们已有 Java 后端转发接口的示意，需替换为实际业务接口；本平台没有新增该路由。React 示例不放平台 token，也不直连平台网关。

后续 GET 查询、取消和关闭会话继续用上表说明，示例不做轮询或会话自动清理。HTTP 202 只表示已受理，不把 `queued` 当作完成。示例仅使用环境变量引用，不包含真实凭证。凭证应由业务后端保存。

API 新运行以“业务平台”来源出现在该项目的运行记录中；其他项目不能读取其输入、结果或会话。既有平台调试与已发布版本保持兼容。

## 与现有项目结合

在场景明确后，由业务后端准备输入、发起任务、查询结果，再根据业务规则展示或处理输出。调用时机、数据边界及结果使用方式需要按具体场景设计。本次没有新增业务转发接口，也没有接入数据治理项目或读取它的实际数据。
