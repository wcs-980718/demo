# AI 评测治理 P4 前端实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 在 AI 中台新增一级“评测治理”页面，打通总览、案例、评测集、任务结果、实验对比和发布门禁的完整操作主流程。

**架构：** 使用一个顶级路由 `/evaluation` 和 URL 查询参数 `view` 切换六个子视图。API、类型、纯展示逻辑和页面组件分离；React Query 负责服务端状态，Ant Design 提供可访问表单/表格/弹窗，现有中台语义变量与 Lucide 图标保持视觉一致。

**技术栈：** React 18、Umi Max 4、TypeScript、Ant Design 6、TanStack Query 5、Axios、Lucide React、Node Test。

**规格：** 后端仓库 `docs/superpowers/specs/2026-08-29-AI数据飞轮与评测治理模块设计及建设跟踪.md`

## 全局约束

- 所有文档使用直接中文文件名。
- 页面只增加 `/evaluation` 顶级路由，不创建多层动态路由。
- 页签状态写入 `?view=overview|cases|datasets|runs|experiments|gates`，刷新和后退可恢复。
- 列表不请求或渲染案例输入与期望正文；只有详情抽屉按 ID 获取正文。
- 每个页面只有一个主操作按钮；危险操作必须确认；异步提交期间按钮禁用并显示加载。
- 不使用 Emoji 作为结构图标，只使用项目现有 Lucide 图标。
- 桌面与窄屏共用语义结构；375px 不出现页面级水平滚动，数据表在窄屏转换为可读列表。
- 所有输入具备可见标签，颜色不是唯一状态线索，图标按钮具有 `aria-label`，焦点样式不移除。
- 动效只使用 opacity/transform，150–250ms，并尊重 `prefers-reduced-motion`。
- 每个纯逻辑行为先写失败测试并确认失败，再实现。
