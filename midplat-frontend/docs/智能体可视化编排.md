## 使用流程

1. 在智能体平台点击“新建智能体”，填写名称、项目及首个任务，点击“创建并开始编排”。已有智能体可从详情点击“拖拽编排”，或直接进入“工作流”。
2. 在“智能体配置”中选择默认模型，填写角色规则或关联固定提示词修订。
3. 拖入模型处理、条件分支、并行分支、结果汇合节点。也可使用顺序处理、条件路由、并行分析模板。
4. 从节点连接点拖出连线；也可在右侧“关联后续节点”中选择目标并添加连线。选中连线按 Delete，或点击右侧删除按钮可移除连线。
5. 点击节点配置模型与指令；开始节点中配置任务及能力资产。任务资产由该任务的模型节点共同使用。
6. “保存草稿”允许保留未连完整的流程。“生成智能体”检查全部任务，确认后生成并保存配置。然后前往版本与发布，发布、上线并调试。

工作流页整页就是编排画布：不再重复渲染“工作流”页面标题、发布按钮与信息横幅，画布高度铺满视口，右上角的关闭按钮返回上一页。页面自上而下依次是编排标题与“图解教程”、任务行（任务选择、保存草稿、生成智能体）、左侧节点面板 / 中间画布 / 右侧检查器，底部状态栏显示任务与节点数量以及“保存草稿 › 生成配置 › 发布并运行”的推进顺序。检查器与任务行的长文本（模型名、任务名）不会撑破面板，超出宽度统一用“…”收尾。

支持多任务编辑、画布位置保存、自动布局、缩放、配置下载、修改冲突提示和工作台内离开提醒。只读身份可查看，不能修改或生成。

## 页面内图解教程

点击“可视化编排”标题旁的“图解教程”，可以随时查看操作说明。教程不会改动当前草稿，在只读模式下也可使用。

- **逐步操作：** 模型与角色 → 任务与能力 → 添加与配置节点 → 连接执行流程 → 保存与生成 → 发布与运行。每步都有编号标注图、操作位置、功能解释、示例和提示。
- **节点功能：** 开始、模型处理、条件分支、并行分支、结果汇合与输出的说明，以及顺序、条件、并行三种连接示例。
- **常见问题：** 保存、生成、发布、上线和运行的区别；生成检查失败、能力资产、节点跳过与旧会话版本的处理方式。
- 图片支持“查看大图”；窄屏可横向滑动或用方向键查看。Escape 可关闭弹窗并返回原编辑位置，未保存内容保留。

## 执行语义

- 连线决定实际依赖，卡片坐标不改变执行顺序。旧的无连线配置继续按原节点顺序执行。
- 条件节点判断原始输入或上游输出，支持包含、相等、不等、数值大小、为空和非空。可通过点分隔路径读取 JSON 字段，例如 `risk.score`。无效 JSON 或非数字的数值比较会报错，不默默选择另一分支。
- 条件的“满足”和“不满足”出口都必须连接；每次只执行命中路径，另一条路径及其不可达后续节点标记为跳过。
- 并行节点同时启动分支。单个任务最多同时执行 4 个模型节点，单个运行进程共享最多 8 个模型工作线程；仍受既有项目模型调用限额约束。
- 汇合节点等待相关前置节点完成或跳过，只合并实际执行结果。一个结果直接传递，多个结果按来源节点标识形成 JSON 对象，字段值是各分支的输出文本。最终输出节点采用相同规则。
- 任一分支失败会终止任务并取消其他分支；取消运行也会停止所有活动分支，不继续汇合。
- 每个模型节点接收角色、任务、节点指令、原始输入及已执行前置结果；有会话历史时也会带入。新运行事件展示节点输出、条件选择和跳过状态。
- 每个智能体最多 20 个任务，每任务最多 30 个节点；单个并行节点最多关联 8 个分支。禁止环路，发布要求所有节点连通开始和输出。当前提供无环流程，不提供循环节点。

## 保存、生成与版本兼容

画布作为任务的 `workflow` 字段保存在现有草稿 JSON 中，包含版本号、坐标和连线；节点可携带 `kind` 与 `condition`。无需新增数据库表或复制环境数据。

`PUT /api/fusion/projects/{project}/draft/generate` 使用已有会话、CSRF、项目权限、模型授权检查和 `expectedRevision` 并发保护。后端检查完整流程后保存草稿并记录生成审计；发布仍使用现有独立操作，在发布阶段解析固定资产修订并核对模型能力。

发布快照包含连线和条件规则。路由节点不获得模型调用票据；模型节点才携带模型授权。新编译版本为 `fusion-config-v3`，运行版本为 `fusion-runtime-v2`。旧版本继续由已有不可变运行包机制维护。传统表单保留任务设置，已使用画布的任务在画布中修改节点结构，以避免表单破坏关联。

上线时须同步更新前端、中台接口以及承载 `com.agenthubfusion` 的智能体管理/运行服务。环境和数据库配置沿用项目已有发布要求，本次未修改它们。
